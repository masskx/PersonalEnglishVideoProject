# Images2 参考图编辑关键姿态

## 适用范围

用于小黑在同一场景中需要保持人物、机位、道具与构图连续，只改变动作结果的镜头。
当前视觉金样位于 `assets/visual-baselines/mit-miss-sunburst/`：下方小黑把橙色信封递给
桌面上方小黑。它验证了 `gpt-image-2.5-sunburst` 的 `/v1/images/edits` 比逐张独立生图
更能保持角色和场景关系。

金样约束制作方法，不约束具体物件。后续题目不得机械复刻桌子、信封或人物站位；应按
教学语义重新设计场景。

## 默认链路

1. 先从已验收的小黑素材和 `references/ian-xiaohei/` 中选出视觉锚点；优先直接把已接受的
   角色/母版图作为编辑参考。文字风格描述不能代替图像锚点，不能用泛化的 black bean、
   stick figure 提示词从零起图后直接进入制作。
2. 先确定一张清楚的动作母版：纯白背景、小黑是语义主角、构图简洁、角色比例和道具关系
   明确。未经白底人工验收的生成图不能充当母版。
3. 对可表现因果变化的词根动作拆成 `before / change / result` 三态；每态必须提供新的因果
   信息。若概念没有真实状态变化，不得为满足三张图而编造动作。
4. `before` 使用已接受母版；`change` 和 `result` 分别从同一母版编辑，不能以前一个编辑
   结果连续派生，避免累计的人物、机位和线条漂移。
5. 编辑提示先写“必须保持不变”的人物、机位、主体比例、构图、线条和非目标道具，再只描述本状态允许变化的
   手臂、身体位置与语义物件归属。
6. 默认模型为 `.env` 中的 `OPENAI_IMAGE_EDIT_MODEL=gpt-image-2.5-sunburst`；凭据、地址和
   模型统一保存在项目根 `.env`，不得写进计划、报告、代码或聊天输出。
7. 接口返回后统一到 2048×1152，去底并输出透明 PNG；先运行素材技术 QA，再做白底人工风格
   与语义验收。技术通过不等于素材可用。
8. 在配音生成、精确场景计时和 Remotion 装配前，输出整组三态的 contact sheet，并把每张
   原图 100%/200% 复合到纯白背景检查。逐张对照视觉锚点及小黑验收规则；手机缩图再确认小黑
   仍清楚可辨、动作可读。任何一态不合格，先重做或剔除该组，不得靠叠层遮掩或补救。
9. 在 Remotion 中把姿态作为互斥静态图层挂载：区间半开、不重叠不留空，`enter/exit` 设为
   `none`，三态固定同一机位、角色比例和图层锚点；切点对齐旁白语义。需要变化的是姿态/物件
   关系，不是整张图的位置。
10. 核心语义物件保持局部、手绘、从属；不得以大块几何/SVG 风格面板、全画布机械层或轨迹线
    覆盖、框住或抢走小黑的视觉主导权。代码绘制仅用于小型标签、规则及确有口播依据的局部方向
    辅助，不承担角色动作本身。
11. 默认直接切换静态姿态并留出可读停顿。禁止整幅图循环漂浮、呼吸、旋转或无因果弹跳；若确
    有小幅接触/回弹关键帧，必须有语义理由且不能代替三个离散状态。
12. 检查动作前、接触、结果及每个切换点 `-1/+1` 帧；渲染后再从实际 MP4 抽查每个动作组的
    状态画面和切点，确认姿态确实逐态更换、没有遮挡/双影/闪帧，再检查手机尺寸可读性。

## 通用计划与命令

计划文件遵循 `planning/visual-baselines/mit-miss-sunburst-plan.json` 的结构。每个 shot 提供
一张 `reference` 和若干 state；state 可以引用已接受 source，也可以写编辑 prompt。

```powershell
# 只检查计划，不调用接口
npm run replica:keyposes:edit -- --plan=planning/visual-baselines/mit-miss-sunburst-plan.json

# 实际生成缺失姿态
npm run replica:keyposes:edit -- --plan=planning/visual-baselines/mit-miss-sunburst-plan.json --generate

# 只迭代一个动作/状态
npm run replica:keyposes:edit -- --plan=<plan.json> --generate --only=<shot-id> --pose=<state-id> --force
```

## 接受标准

- 实际小黑视觉锚点可辨：身体比例、实心黑色主体、白点眼睛、手脚轮廓、冷静表情和手绘线条
  与项目已接受样例一致；不能只因“像黑色小人”或机器 QA 通过就放行。
- 小黑身份、数量、大小和眼睛位置没有无故变化。
- 机位、构图、主体边界和主道具设计保持稳定。
- 三态中小黑始终是第一视觉主体；道具可与动作接触，但不能遮住眼睛、躯干或关键肢体，也不能
  用大面积形状在视觉上盖过角色。
- 语义物件的归属一眼可见，例如信封从发送者手中转到接收者手中。
- 没有新增文字、签名、Logo、装饰箭头、蓝色机械叠层、阴影、渐变或纸张纹理。
- 透明 PNG 通过分辨率、四角透明、主体覆盖率、残绿和边缘检查。
- contact sheet、纯白底原尺寸复核与手机缩图复核都已人工完成；素材自动报告只证明技术条件，
  不证明小黑画风、主体层级或教学可读性。
- 三个姿态在成片中是可读的因果链，而不是三个近似静帧。

## 失败处理

- 人物或道具漂移：回到同一母版重做，不以上一次编辑结果继续编辑。
- 角色变成火柴人、比例/眼睛/线条偏离样例：拒绝该候选；改用已接受图像作为直接编辑锚点，
  不以加粗轮廓、加道具或代码贴片把错误素材修成“差不多”。
- 画面变成商业卡通/PPT：缩短提示词，只保留角色、动作和一个关键物件。
- 白底遮住文字：必须转透明 PNG；不要通过降低整幅白底图透明度掩盖问题。
- 有 SVG 感/画面像被遮罩：先查渲染层级与实际绘制素材。即使没有 SVG 文件，大块几何 raster
  道具、面板和跨画布轨迹也属于同一视觉失败；移除或缩小到局部语义物，恢复小黑主体，不通过
  再叠一层图形补救。
- 姿态正确但画面死：先调整切点、停留时间与文字节奏，不重新叠加全屏 SVG 或机械运动。
