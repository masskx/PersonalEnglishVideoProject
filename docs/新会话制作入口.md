# 新会话制作入口

本文件给新窗口、新任务或更换智能体（Codex / Claude）后使用，不依赖历史聊天。规则总表在根目录
[AGENTS.md](../AGENTS.md)；画面、动画、声音、封面和整片预览的唯一标准是[当前视频制作基准](当前制作基准.md)。
本文件只补充：怎么开始、命令顺序、每一步产物放在哪里。

## 1. 开工前（每次会话）

```bash
git pull
git lfs pull                      # 拉取图片、音频、视频（只拉需要的期数也可：git lfs pull --include="public/assets/replica/<期名>/**"）
npm install                       # 首次或依赖变化后
npm run hooks:install             # 每个克隆一次：提交前自动扫描密钥
npm run keys:check                # 只显示密钥是否设置与长度
```

然后读：`AGENTS.md` → `docs/当前制作基准.md` → `planning/production-defaults.json` →
`docs/选题与自动制作规则.md` → 制作 Skill（`.agents/skills/make-xiaohei-english-video/SKILL.md`，
词根类再读 `build-root-word-video/SKILL.md`）。

## 2. 指定题目还是只指定栏目

- “做一期 spect 词根”“做 affect 和 effect 的辨析”“用这道四级题讲阅读定位” → 已指定题目，严格按内容做。
- “做一个词根视频 / 词根辨析视频 / 易混词视频 / 四级写作、阅读、翻译视频” → 只指定栏目：自主查重选题，
  直接完整制作，不让用户从候选中挑。

查重看：`planning/topic-history.json`、`src/replica/projects/registry.ts`、`src/cet-*`、`src/cet6-*`、
`outputs/`，以及本机 `work/` 里还没交付的草稿。选定后先在台账登记 `in_progress`。

## 3. 词根 / 词汇 / 易混词期：命令顺序

| 步骤 | 命令 | 产物 |
| --- | --- | --- |
| 1 词图计划预检 | `npm run replica:preflight -- --project=<期名> --plan-only` | 映射是否完整（每词：释义、动作、场景、姿态、总结行） |
| 2 生图计划 | `npm run replica:images -- --project=<期名>` 或 `npm run replica:keyposes:edit -- --plan=<计划>` | 只显示要生成的图，不花钱 |
| 3 生图 | 上一条加 `--generate` | `assets/green-screen/<期名>/` 源图 → `public/assets/replica/<期名>/` 运行时图 |
| 4 素材白底复核 + 完整预检 | 人工看图，再 `npm run replica:preflight -- --project=<期名>` | 不通过就停，不得配音和渲染 |
| 5 配音 | `npm run replica:voice -- --project=<期名>`（计划）→ 加 `--generate` | `public/assets/audio/replica/<期名>/` |
| 6 校验 | `npm run replica:validate -- --project=<期名>` | 时间轴、素材、来源扫描、画面节奏闸门 |
| 7 一条命令交付 | `npm run replica:produce -- --project=<期名> --stage=deliver` | 见第 5 节交付清单 |
| 8 人工终审 | 打开 `outputs/<期名>/review/full-preview/` 连续看完；手机外放 + 耳机各听一遍 | 填 `content-qa.md` |

单独重跑某一步：`replica:render`（横屏）、`replica:cover`、`replica:full-preview`、`vertical:render`、
`vertical:stills`（竖屏版式抽查）、`xhs:cards`、`replica:copy`（发布文案）。都带 `-- --project=<期名>`。

新词根期一律**复制 clud-clus 一套文件**再改内容：`src/replica/projects/cludClus.ts`（期定义，已接好
ten-tain 同款连续舞台 `buildContinuousStage`）、`src/replica/cludClusStoryboard.ts` + `cludClusStoryboardData.json`
（分镜）、`cludClusAudioManifest.json`、`cludClusIllustrationPrompts.ts`、`planning/clud-clus-keyposes.json`，
再在 `registry.ts` 注册。不要复制 pon-pos、cred、duc-duct 等老期数：它们用已淘汰的 `'default'` 渲染，
新期用它会被 `replica:validate` 拦下。

分镜约定（自动连续舞台靠它识别）：词页 id 为 `<word>-word`，主词文字层 id 为 `<word>-word-word`，三态图片层
id 以 `-before` / `-change` / `-result` 结尾，主词放左栏（x≈95）或右栏（x≈980）交替；封面写 `wordHighlights`。
旁白里的例句、中文释义、搭配和对比要做成画面层，在旁白说到时进场（参照 clud-clus 的 `-example`、`-gloss`、
`-note` 层）。`replica:validate` 的节奏闸门会报出哪一段静止太久。

## 4. 四六级方法课：命令顺序

| 栏目 | 目录 | 命令 |
| --- | --- | --- |
| 四级写作 | `src/cet-writing/` | `writing:voice` → `writing:prepare` → `writing:render` → `writing:delivery` |
| 四级翻译 | `src/cet-translation/` | `translation:voice` → `translation:prepare` → `translation:render` → `translation:delivery` |
| 六级阅读 | `src/cet6-reading/` | `cet6:voice` → `cet6:prepare` → `cet6:render` → `cet6:delivery` |
| 六级写作 | `src/cet6-writing/` | `cet6w:voice` → `cet6w:prepare` → `cet6w:render` → `cet6w:render -- --video` → `cet6w:delivery` |

每个栏目最后再跑 `npm run xhs:cards -- --project=<期名>` 出小红书方法卡。新栏目：复制最接近的栏目目录，
改 `lesson.ts`（讲稿、例句、练习）和 `xhs.ts`（MethodDeck），在 `src/replica/xhs/methodDecks.ts` 登记，
至少生成 3 张不同的小黑插图（题目、关键步骤、练习）。四六级与词根期用同一套视觉和验收标准。

## 5. 交付清单与目录

每期一个交付目录 `outputs/<期名>/`（用户确认发布后改名为 `outputs/<期名>发了/`，两者不并存）：

- 横屏成片 `<期名>.mp4`（1920×1080）、竖封面 `cover.png`、横封面 `cover-landscape.png`
- `publish-copy.md`（发布文案）、`release.json`（保持 draft）、`content-qa.md`（人工核对）
- `review/`：整片预览 `full-preview/`、联系图、技术报告
- `vertical/`：抖音竖屏完整版、预告短片、复习卡
- `xiaohongshu/`：3:4 图文卡、`xhs-note.md`、联系图
- 四六级另有 `worksheet.html` 练习单

`work/` 是本机临时目录：渲染暂存、草稿、试验、淘汰图都放这里，整个目录被 gitignore，不进仓库，
也不在工作台展示。可以随时清空。

## 6. 收尾

```bash
npm run project:test        # 管理、竖屏版式、小红书卡片回归 + 密钥扫描
npm run project:check       # 交付文件与运行时素材完整性
npm run project:inventory   # 刷新 00-打开工作台.html 与 PROJECTS.html
```

然后：台账改 `produced` 并写产物路径，`docs/production-log.md` 记一条，提交并推送。完成制作不等于发布；
不自动上传平台，不替用户发消息。
