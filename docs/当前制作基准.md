# 当前视频制作基准

版本：2026-09-29  
适用范围：项目内所有英语视频，包括后续词根、词汇辨析、四集系列和四六级写作、阅读、翻译视频。

## 这份文件的作用

这是项目的唯一视觉与成片基准。新会话、更换 Agent、增加栏目或修订旧片时，先读本文件，
再读根目录 `AGENTS.md`、`planning/production-defaults.json` 和相应 Skill。旧成片和历史
审计文档只用于追溯，不再作为新视频的制作规则。

用户后续明确提出的新要求优先；除此之外，不得回退到历史模板、旧动效或旧生图路线。

## 固定视觉规则

1. **生图**：使用内置 `image_gen` 生成真实栅格图。纯白画布，实心黑色小黑，白点眼，
   手绘抖线，少量橙红蓝教学色；小黑必须是语义动作的主角。先生成构图锚点，再从同一
   机位编辑 `before / change / result`。图片中不烘字、不使用 SVG/代码几何图冒充插画，
   不用商业卡通、3D、素材拼贴或重复人物。
2. **基本套路**：前 1.5 秒给出具体问题或结果，3 秒内发生第二次视觉变化；随后用一个
   可看懂的动作讲清知识点，加入例句、迁移或练习，结尾做可复述的总结。画面使用至少
   三种有教学意义的构图，文字与图片分区，留白是排版的一部分，不用空白凑时长。
3. **动画**：所有动效由 Remotion 帧驱动。使用平滑上移、滑入、遮罩揭示、词素组装、
   关键姿态切换和白底淡出；重点信息要有可读停留。禁止随机漂移、持续呼吸、乱跳、
   镜头抖动、整屏 SVG 机械层和每层都一样的弹跳。
4. **声音**：抖音节奏略快、明亮、有推进感；使用可听见的纯音乐，旁白期间自动压低，
   手机外放和耳机都必须听清人声。音乐不能盖住中文辅音或英文单词。
5. **封面**：所有栏目共用词根封面母版及横版伴侣，只替换栏目内容、标题、例句或语义
   插画，不制作简化白卡或另起一套封面风格。

## 固定制作链路

`查重选题 → 登记制作中 → 资料核对 → 自然讲稿 → 内置 image_gen 生图 → 白底角色与
构图复核 → 配音与混音 → 帧驱动文字和语义动画 → 完整渲染 → 整片预览 → 竖屏完整版/预告/复习卡
→ 双封面与文案 → 音视频/内容验收 → 台账、日志和工作台更新`

**竖屏交付（2026-10-12 起默认）**：抖音推荐流是竖屏，横屏只占约三分之一屏幕。横屏成片通过后运行
`npm run vertical:render -- --project=<slug>`，由同一 storyboard、配音和插图重排为 1080×1920，
产出 `vertical/` 下的完整版、约 40 秒预告和复习卡。竖屏不重新生图、不改讲稿；首帧即有题目和小黑，
正文与字幕在抖音安全区内，结尾停在白底总结页以便循环。行动号召与推广配置见
`planning/growth-promotion.json`。

每期运行时图片必须来自自己的 `public/assets/replica/<slug>/`；参考图只用于生成，不能
跨期直接挂载。完整视频、双封面、文案和检查记录必须进入 `outputs/`。

## 最终整片闸门

最终渲染后必须运行：

```powershell
npm run replica:full-preview -- --project=<slug>
```

必须打开低清整片连续观看，并查看每页联系图，确认：

- 文字没有溢出、截断、错误换行或贴边；
- 文字与插画比例协调，留白有意图，没有大片空白；
- 场景切换、关键姿态和文字动效连续；
- 手机尺寸仍能读清字幕、单词和重点；
- 背景音乐可听见但不盖人声。

脚本发现文字布局错误时直接失败；人工整片观看是最终通过条件。只看中点截图不能代替
整片预览。

## 旧规则处理

历史成片、旧模型调用记录、旧版脚本和审计报告保留在原位置用于追溯，但不再指导新片。
特别是以下做法已经停用：以 Seedream/即梦作为默认生图、用 SVG 或代码几何图替代主插画、
每期复制同一 PPT 卡片、用持续漂浮掩盖静态画面、只看抽帧不看整片，以及为四六级栏目
另起一套低规格视觉链路。
